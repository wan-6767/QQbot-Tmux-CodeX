# 文本清洗与转发

## 两条独立路径

自动追加面向阅读：只发新增正文、完整菜单、真实错误和任务结束标记。
`/tmux sel 001 tail 100` 面向核对：返回最近指定行数的原始终端文本，包括工具操作、diff和编辑框。
二者不调用LLM，不生成摘要，不改动终端或Codex输出。

| 内容 | 自动追加 | tail快照 |
| --- | --- | --- |
| 自然语言说明、回答、建议 | 按完整段落追加 | 原样保留 |
| 正文中的代码块、列表、表格 | 保留结构和缩进 | 原样保留 |
| 模型、权限、确认、输入菜单 | 识别后整体发送，不只发光标变化的行 | 原样保留 |
| Ran、Explored、Edited、Added、Deleted、Called及子项 | 默认隐藏 | 保留 |
| Opened、Clicked、Fetched、Searched、Browsing等网页操作 | 默认隐藏 | 保留 |
| 文件改动树、行号diff、`+ Show details`、折叠日志 | 默认隐藏，包括裁切后残留的片段 | 保留 |
| 普通工具退出记录、工具输出中的OK | 不当作正文发送 | 保留 |
| HTTP 429、5xx、明确的服务/请求失败 | 保留并对常见凭据脱敏 | 原始显示 |
| `Worked for 34m 23s ...` | 完成后发送，表示本轮结束 | 保留 |
| 编辑输入回显、进度动画、历史菜单 | 不当作新增回答 | 保留 |

## 段落和换行

按空行区分自然段，围栏代码块中的空行不拆分代码。运行中的未完成尾段等待稳定或完成后再发，避免一行一条。
合并由终端宽度造成的普通正文软换行：中文直接接续，英文补空格，连续URL不插入空格。
标题、列表、表格、引用、围栏/缩进代码和明确的换行标记不按普通正文拼接。

先识别工具块及其子行，再提取正文；不能只删除标题，否则`└ Search...`、diff行或OK会泄漏成独立消息。
HTTP错误有单独识别路径，不能因出现在工具块里就一起洗掉；正文代码中的数字503或429不自动当报错。

## 增量、菜单和结束

每个编号都有独立的屏幕基线和投递队列。已发送的正文不再重发，确认失败的段落保留并退避重试。
进入时发送100行并建立基线，之后即使你不发新消息，也监听终端的新输出。
菜单使用完整可见区域识别和整体回显，光标上下移动不做“仅两行”的正文增量。
`tail N`仅重置指定编号的追加基线，不影响其他连接；随后仍继续监听。
超出QQ单条文字限制的一个完整文本体使用一个`.txt`附件，不按行切碎，也不静默截断。

## 原始快照

```text
/tmux sel 001 tail 200
/tmux tail 200 sel 001
/tmux sel 001 tail100
```

N可选1–5000；历史不足返回已有文本，受tmux实际历史缓冲限制。旧list100会提示新语法，绝不会当成终端输入。
原始是“tmux文本快照”，不是像素截图：移除控制字符，tmux会合并其标记的软换行；不应用正文噪音过滤，也不承诺保留颜色或像素布局。

## 边界与测试

这是定时屏幕采样，不是终端程序原生事件协议。极快重复且完全相同的输出、采样间已经滚出缓冲的内容和未知TUI仍可能无法可靠辨认。发生疑问用tail核对，不据此重复提交可能已执行的命令。
过滤针对Codex式输出，不保证任意shell日志自动成为可读对话。原始快照可能含敏感信息，群里所有成员都可看到。

实现：`src/tmux_bot/terminal_relay.py`负责正文/工具/菜单/段落识别，`multi_relay.py`负责每个连接的增量、队列和发送。
回归：`tests/test_relay.py`、`test_prose_wrap.py`、`test_multi.py`覆盖工具子项、残缺diff、网页噪音、真实错误、代码/换行、完整菜单、重复短答和独立投递。
