# 使用手册

## 一个 bot，多台服务器，多条终端连接

私聊直接发送；群里每条指令都 @当前 bot：

```text
/tmux ls
/tmux sel 001 ent
/tmux sel 002 ent
/tmux sel 001 send 检查这个项目的测试结果
/tmux sel 002 send /model
/tmux sel 002 key down
/tmux sel 002 key enter
/tmux sel 001 tail 100
/tmux sel 001 ext
```

`ls` 按服务器分组，`local` 是本机，远程名称由配置决定。编号001–999持久化对应真实窗格，不是列表排序。重排、改名、正常重启不改编号；关闭或替换的窗格不会复用旧编号。所有窗格均可获得编号。

回显标注 `[001 · local · work:0.0]` 或 `[012 · research · train:0.1]`。每个编号独立拥有连接、发送目的地、增量基线、失败队列和计时；退出001不影响002，不停止终端任务。

标签中的`会话名:窗口编号.窗格编号`是tmux原生位置，例如`work:1.1`。不同会话各自拥有编号1的窗口和窗格，因此后缀可以相同；bot的固定编号仍不同。tmux的起始编号取决于自身配置，可能从0或1开始。

## 指令速查

| 指令 | 行为 |
| --- | --- |
| `/help` | 全局功能总览 |
| `/tmux help` | 终端详细帮助 |
| `/file help` | 文件收发详细帮助 |
| `/tmux ls` | 本地及远程窗格、固定编号、连接及占用状态 |
| `/tmux sel 001 ent` | 接入，先返回最近约100行，再持续追加 |
| `/tmux sel 001 send 文字` | 原样输入并回车 |
| `/tmux sel 001 send /model` | 交给指定终端的程序命令 |
| `/tmux sel 001 send /goal resume` | 原样发送goal指令 |
| `/tmux sel 001 type 文字` | 输入但不回车 |
| `/tmux sel 001 key enter` | 回车确认 |
| `/tmux sel 001 key up` | 方向键，每次一键 |
| `/tmux sel 001 send ent` | 将保留词ent当普通文字发送 |
| `/tmux sel 001 tail 100` | 原始100行快照，只重置这一连接的追加进度 |
| `/tmux sel 001 ext` | 仅断开这一连接，任务继续运行 |
| `/group bind`、`/group status`、`/group unbind` | 私聊管理群绑定 |

目标`sel 001`与操作可交换：`/tmux ent sel 001`、`/tmux tail 250 sel 001`、`/tmux key up sel 001`，模块内部不能打乱。发送内容统一使用`send`，例如`/tmux sel 001 send 文字`，或`/tmux send 文字 sel 001`。

tail N支持1–5000行，tail100也可识别，历史不足返回已有内容。旧list100拒绝执行并提示新格式，不输入终端。

按键支持字母/数字/标点、F1–F24、方向/编辑/翻页键及Ctrl/Alt/Shift组合，例如`ctrl+c`、`shift+tab`、`alt+enter`、`ctrl+shift+left`。详见[键盘映射](keyboard.md)。一次一键，不支持重复次数。Ctrl+C可能中断任务，Ctrl+D可能结束程序。

`ent`是接入，回车是`key enter`；`ext`是断开，不是退出程序。`send 内容`原样输入并回车，`type 内容`只输入不回车。终端程序指令也作为内容发送：无引用的裸`/goal resume`会被bot拒绝，应使用`/tmux sel 编号 send /goal resume`。

新版不再执行旧`/tmux select 1`、`/tmux exit`。没有引用终端回复时，普通文字和裸`/model`仍不能确定目标，必须带编号和send；公开bot指令统一以`/`开头。

## 引用回复直接输入

引用本bot带`[001 · 服务器 · 终端]`标签的终端回复，在QQ引用回复中直接写新消息，就相当于`/tmux sel 001 send 新消息`，自动回车。无需先切换默认窗口；引用哪个编号就输入哪个窗口。

```text
引用：[001 · local · code:0.0] 的终端回复
发送：检查刚才的修改并运行测试
效果：只把这句新文字输入001并回车

引用：[002 · research · train:0.0] 的终端回复
发送：/model
效果：向002输入/model并回车
```

群里引用后仍需@本bot。进入时的上下文、自动追加正文、菜单、tail快照及超长文本附件的回复均可引用；不会把被引用的旧内容或附件一起输入终端。上传文件仍走文件接收，不自动提交路径。

`/help`、`/tmux`、`/file`、`/files`、`/download`、`/group`、`/sub2api`仍作为bot指令处理。需要把这些词输入终端时使用完整`/tmux sel 编号 send 内容`。例如引用001后发送`/tmux sel 002 key enter`，仍明确操作002；引用后只写`key enter`则会将这两个词作为文字输入并回车。

只匹配同一聊天、同一操作者收到的本bot终端回复，不从任意复制的编号或用户消息猜测目标。未识别、引用过旧、窗口断开或已关闭时会提示，不自动重连或转发到其他窗口；断开后先`/tmux sel 编号 ent`。升级前的旧回复没有引用索引，先用`/tmux sel 编号 tail 100`取得新回复再引用。

引用索引保留最近2048条成功终端投递，随实例重启恢复。QQ未提供可匹配的消息ID且引用内容被客户端截短时，可能无法识别；可引用新回复或改用完整send指令。

## 自动追加和原始快照

进入时任务已经运行，也会持续追加，无需再发消息触发。正文和代码示例按完整段落转发，合并终端宽度导致的软换行；保留429/5xx错误及`Worked for ...`结束字段。工具操作、diff和折叠日志只在`tail 100`原始快照中出现。模型/权限/确认菜单整体回显，不只发光标改变的几行。

超长文本用一个完整`.txt`附件，不逐行拆分、不静默截断。QQ拒绝投递时保留队列并退避，重启补发未确认的段落；QQ已接受但客户端丢失回执时不能保证严格恰好一次。屏幕采样不是程序原生消息流，极快且完全相同的答案、未知TUI可能无法正确识别，有疑问用原始快照核对。

每个编号单独计算静默：本人输入或成功投递的新输出续期；双方30分钟无消息才断开。轮询、隐藏日志和其他编号的消息不续期。重连用原编号`ent`；如果窗格已关闭，先重新`ls`。

输入或SSH超时先`tail 100`核对，不能据报错认定输入未执行，不能盲目重发。输入收据全局去重，避免同一QQ事件因重试发往不同编号。

## 私聊、群聊和权限

同一编号只能绑定一个聊天目的地，不能同时转发到私聊和群聊。切换前在原聊天`ext`，其他编号不受影响。每个AppID的QQ OpenID独立；多个bot仍通过共享内核锁避免同时占用同一真实窗格。

群里只有绑定本人的@消息可以输入，但输出全群可见。所有窗格共用一个QQ发送额度管理器，窗格变多不增加平台限额；被动窗口耗尽后仍需QQ允许主动消息，服务器不能绕过。修改群绑定前退出该群全部连接。

输入框`/`快捷面板提供17个入口：

- 终端：`/tmux ls`、`/tmux sel`、`/tmux send`、`/tmux key`、`/tmux tail`、`/tmux ent`、`/tmux ext`、`/tmux type`。
- 文件与额度：`/file dl`、`/file rm`、`/sub2api usage`。
- 帮助：`/help`、`/tmux help`、`/file help`。
- 群绑定：`/group status`、`/group bind`、`/group unbind`。

选中入口后补完整参数：选`/tmux key`后补`enter sel 001`，选`/tmux ent`后补`sel 001`，选`/file dl`后补绝对路径。也可以选`/tmux sel`后补`001 send 文字`，两种模块顺序都可使用。不完整指令只提示格式，不输入终端。启动同步与手动注册使用同一目录，重启不会恢复成三个入口。面板只注册本人私聊，群里仍需@bot；客户端同步延迟时可手动发送。

上传文件、图片、语音会缓存并返回本机绝对路径，不自动输入终端、不识图、不转写；`/file dl /绝对路径`下载本机文件，`/file rm`精确清理缓存。无需已连接窗格，详见[文件收发](files.md)。远端不能直接读取本机缓存。

工具不调用模型，不提供日记或计划。`/sub2api usage`通过[可选额度插件](sub2api.md)刷新本机账号窗口和积分。终端自身有多少权限，绑定QQ就能使用多少权限。过滤规则见[文本清洗](text-cleaning.md)。

远程接入见[SSH配置](remote.md)。每次ls重新检查连接，远端不可达会显示“连接异常”及诊断；本机和其他远端仍可用，原编号保留，不重新分配。连接恢复后原窗格继续使用旧号。
