# 使用手册

## 一次完整操作

私聊直接发送，群里每条消息都 @当前bot：

```text
/tmux ls
/tmux select 1
检查这个项目的测试结果
/tmux list100
/tmux exit
```

进入后普通文字直接输入并回车。bot只是传话，不生成答案，不替终端程序决定模型或权限。Codex、shell和其他TUI沿用各自的权限、上下文和费用。

## 窗格与连接

| 指令 | 行为 |
| --- | --- |
| `/help`、`/tmux help`、`/tmux` | 完整终端帮助，不退出现有连接 |
| `/tmux ls` | 列出窗格和占用者 |
| `/tmux select 1` | 按最近列表编号进入 |
| `/tmux select %4` | 按稳定窗格ID进入 |
| `/tmux select work:0.0` | 按完整位置进入 |
| `/tmux exit` | 释放连接和占用，终端任务继续运行 |
| `/tmux reconnect` | 重连静默断开的原窗格，不能抢其他bot占用 |

每次进入先返回约100行原始上下文。此后即使你不再发消息，终端有新的完整正文也会自动追加。只有双方都连续30分钟没有消息才断开；轮询和终端上被隐藏的操作日志不算QQ互动。

一个bot不能同时向私聊和群聊转发同一连接。切换前在原聊天 `/tmux exit`；从另一聊天列出窗格不会偷走发送进度。退出不会杀死shell、Codex或tmux会话。

## 输入和菜单

| 指令 | 行为 |
| --- | --- |
| 普通文字 | 原样输入并回车 |
| `/tmux type 文字` | 输入但不回车，可补充或用退格修改 |
| `/tmux send /help` | 把机器人保留命令作为文字交给终端 |
| `/tmux key enter` | 回车/确认 |
| `/tmux key esc` | 取消/返回 |
| `/tmux key up`、`down`、`left`、`right` | 方向键，每次一键 |
| `/tmux key tab`、`space` | 补全/切换焦点、空格 |
| `/tmux key backspace`、`delete` | 删除光标前、后的字符 |
| `/tmux key home`、`end`、`pgup`、`pgdn` | 行首、行尾和翻页 |
| `/tmux key ctrl-c`、`ctrl-d` | 中断操作、结束输入，可能导致程序退出 |

例如切换Codex模型：发 `/model`，再发 `/tmux key down`，最后 `/tmux key enter`。菜单完整回显当前选项，不只发改变的一行。该菜单是否存在由终端程序决定。

暂不支持重复次数或任意组合键。多行文字按粘贴处理；不要把“已排队”误当成任务已开始。HTTP提交超时会先核对输入收据；遇到提交不明提示先查看 `/tmux list100`，不要立即重复发送。

## 正文和原始屏幕

| 指令/模式 | 内容 |
| --- | --- |
| 自动追加 | 完整自然语言、代码示例、菜单和真实429/5xx错误 |
| `/tmux list100` | 最近100行原始上下文，并重置自动追加基线 |
| `/tmux screen` | 最近40行原始快照 |
| `/tmux screen 50` | 10–100行指定快照 |
| `/tmux screen100` | List100兼容别名 |
| `/tmux next` | 兼容接收指令；正常无需调用 |

自动追加隐藏工具操作记录、diff、折叠日志和状态栏，不拆成一行一条。工具识别主要适配Codex，其他TUI不保证通用正确。超长文本体用完整文本附件发送；这不等于支持用户附件上传。任务完成时可转发 `Worked for ...` 结束字段。

采样不是终端程序的原生事件流。极快、完全相同且没有观察到运行状态的回答可能无法可靠区分；有疑问时检查原始快照。输入框面板仅注册 `/help`、`/tmux ls`，运行时不附消息下方键盘；面板同步失败仍可手动输入。

## 群聊管理和功能边界

私聊 `/group bind`、`/group status`、`/group unbind` 管理群绑定。群输出公开给全部成员，只有绑定本人可操作。每个AppID身份独立，不共享另一bot的OpenID。

本项目不提供文件上传下载、Sub2API额度、AI秘书、日记或计划；这些与终端转发分开部署。收到图片、语音或文件会拒绝，不下载，不把路径自动输入终端。公开指令统一用 `/`，QQ入口拒绝旧 `#` 指令。
